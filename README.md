# cs465-fullstack
CS-465 Full Stack Development with MEAN

### Architecture
The Travlr Getaways application uses multiple types of fronted development as part of its full stack architecture. The customer-facing portion of the application uses Express with Handlebars views to render the website. Routes and controllers are used to retrieve information from the backend and display it to the customer. JavaScript is also used throughout the application to provide functionality and allow different parts of the application to communicate. The administrative portion of the application uses Angular to create a single page application, or SPA. Angular organizes the application into components, services, models, and routes, which makes it more modular than the customer-facing Express application. The SPA also allows the administrator to move between the various components without loading a completely new HTML page for every interaction. The backend uses MongoDB because it is a NoSQL database that fits in well with the JavaScript-based MEAN stack used for the application. MongoDB stores the travel information as documents, working with the data being passed between the frontend and backend. Mongoose was used to provide a structured way for the Express application to interact with MongoDB. This allowed the application to retrieve, add, and update trip information while keeping the database connected to the API.

### Functionality
JSON differs from JavaScript as it is a data format used to represent information, while JavaScript is a programming language used to create application functionality. JSON is important to the application because it ties the frontend and backend together. When the Angular application makes a request to the API, the API can return the requested information as JSON. The Angular application can then use that data to display trips. JSON is also used in sending information to the APi when adding or updating trips. This allows the different parts of the full stack application to communicate using a common data format. I refactored code several times throughout the development of the application as new functionality was added. One example was moving the original static HTML customer-facing website into Handlebars views for information to be rendered dynamically. Another example was when the Angular SPA was added so that components and services could communicate with the API. Reusable UI components provide several benefits, as components can be created for a specific purpose and then used wherever that functionality is needed. In the Angular application, components such as the trip listing, add trip, and edit trip components each have their own responsibilities, making the application easier to organize and maintain.

### Testing
Together, methods and endpoints allow the frontend to request or modify information through the API. An endpoint identifies where a request is sent, while the method identifies what type of operation is being requested. For example, a GET request to /api/trips retrieves the available trips, while a GET request to /api/trips/:tripCode retrieves a specific trip. The API then uses the appropriate controller and Mongoose model to communicate with MongoDB. I tested the application by using the Angular SPA, Postman, and MongoDB Compass to make sure that requests were working and that changes were being saved correctly. For GET requests, I compared the information displayed in the application with the information stored in MongoDB. For PUT requests, I edited an existing trip and checked that the changes appeared in both the application and MongoDB. I also tested adding and updating trips during development to make sure that the API routes were working correctly. Security was another factor to consider during testing. The administrator needs to log in before accessing protected functionality, and the application uses a JSON Web Token to authenticate requests. This functionality was also tested to verify the JSON Web Tokens using the secret stored in the .env file.
